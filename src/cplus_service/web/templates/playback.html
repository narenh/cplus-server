Playback events

{% include "partials/playback_switch.html" %}

Canopy+ reports playback events (start, pause, resume, stop, chapter changes, intro start and end, credits start), and cplus forwards each one to the webhooks below, for things like dimming the lights. Each Apple TV is named by its room in Canopy+. Events aren't stored; the recent list below clears on restart.

{% include "partials/playback_webhooks.html" %}

What a webhook receives

One JSON POST per event; keys that don't apply are null. Each is sent once, with a {{ timeout }}-second timeout.

  • event — one of:
      {% for kind, description in events.items() %}
    • {{ kind.value }} {{ description }}
      • {% endfor %}
  • room — the room set in Canopy+ on that Apple TV, or null if it was never set.
  • client_id — the Apple TV's Plex client identifier. Stable per device; key on it if rooms are unset or two share a name.
  • position, duration — seconds.
  • watched — stopped only: whether the title was played to the end or left past 90%.
  • chapter — chapter only: index (from 0), title (may be null) and start in seconds.
  • item — what is playing: rating_key (Plex's id), type (movie or episode), title, and for an episode show_title, season and episode; year when known.
  • user — name, the Plex user whose app sent it, and profile (usually empty).
  • received_at — when this server received it, ISO 8601 in UTC.
  • source — always canopy-plus.
  • test — true only for the “Send test event” button above.

Example

{{ example_json }}

In Home Assistant, add an automation with a Webhook trigger, copy its URL into the list above, and read the body as trigger.json — for example, a condition of {{ "{{ trigger.json.event == 'credits_started' and trigger.json.room == 'Living Room' }}" }}. Home Assistant webhooks accept only local-network requests by default, which suits this server if it runs on the same network.
