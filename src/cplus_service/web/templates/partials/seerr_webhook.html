Requests made in Seerr

{% if config.seerr_webhook_secret %}

On. In Seerr, open Settings → Notifications → Webhook, switch it on, and fill in these two fields. Leave the JSON payload as Seerr's default — it already carries everything this reads.

{# Said here rather than only in the README, because the admin most likely to have a customised payload is the one reading this page with Seerr open in the next tab. Extra keys are ignored, so the ask is to keep these, not to go back to the default. #}

If you have customised that payload for something else, it only needs to keep notification_type, request_id, requestedBy_username, subject and media_tmdbid. Anything else in it is ignored. Without the first two, deliveries are accepted and quietly do the wrong thing — the server log says which is missing.

Webhook URL

{{ webhook_url }}

This is the address you reached this page on. If Seerr sees this service under a different name — a reverse proxy, a container network, a LAN address — use the one Seerr can resolve, keeping {{ webhook_path }} on the end.

Authorization Header

{{ config.seerr_webhook_secret }}

Paste this into Seerr's Authorization Header field verbatim. It is the whole of what proves a post really came from your Seerr, so treat it like a password — though note that it authenticates that one endpoint and nothing else, and that endpoint can do nothing but log a request and notify you about it.

Under Notification Types, tick Request Pending Approval and Request Automatically Approved. Anything else you tick is accepted and ignored, so Seerr will not record a failed delivery for it.
