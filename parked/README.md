# Parked: the audiobook aligner

`cplus_align` is the aligner cplus used to run as a sidecar container
(`cplus-aligner`). It turned an uploaded epub plus a book's audio from Plex
into the `version: 1` alignment JSON that cplus serves to Canopy+.

cplus no longer aligns anything itself. It only accepts finished alignments
(**Audiobooks → Upload alignment**), checks them against the album in Plex, and
serves them. This code is kept here for reference and possible reuse. It is
**not** packaged, built into the Docker image or run by the test suite, and
nothing in `src/` imports it.

What it needed when it ran, so whoever picks it up knows what they're taking on:

- **The model and runtime:** about 2.3 GB, downloaded on first use. That's
  torch, the other Python packages in `cplus_align/runtime_lock.json`
  (regenerated by `scripts/lock_aligner_runtime.py`) and the
  `MahmoudAshraf/mms-300m-1130-forced-aligner` model.
- **A compiled extension:** ctc-forced-aligner's C++ Viterbi, built from GitHub
  at commit `64293cc6d711e57666c4a8b098e9fd93b381fd88`. The PyPI package of
  that name is an unrelated project.
- **Resources:** about 2.1 GB of RAM while aligning. At 3 CPUs, a 20-hour book
  took about 4 hours.
- **A shared directory with cplus** (`CPLUS_ALIGN_DIR`) for job files, plus an
  internal cplus route that relayed the audio from Plex. Both have since been
  removed from cplus; see `cplus_align/protocol.py` for the file protocol they
  used.

`tests/` holds the aligner's own tests and the fixtures they used. They ran
under pytest with numpy installed.
